Implement the backend-first MVP:
A. Add backend/application/services/department_pipeline.py with service functions:
   - create_pipeline_for_engagement(engagement, template_id="digital_marketing_pro.weekend_social_launch.v1", created_by=None)
   - get_pipeline_snapshot(engagement)
   - start_stage(stage_state, actor=None)
   - complete_stage(stage_state, outputs=None, actor=None)
   - block_stage(stage_state, reason, actor=None)
   - skip_stage(stage_state, reason, actor=None)
   - attach_deliverable_to_stage(deliverable, stage_state, output_kind="deliverable")
   - attach_asset_to_stage(asset, stage_state, output_kind="asset")

B. The default stage dependency graph should be:
   - strategy_research: no dependencies
   - brand_content: depends on strategy_research
   - crm_lifecycle: depends on strategy_research
   - analytics_performance: depends on strategy_research
   - channel_execution: depends on brand_content
   - qa_compliance: depends on channel_execution, crm_lifecycle, analytics_performance
   - client_approval_ops: depends on qa_compliance

C. create_pipeline_for_engagement should:
   - create/reuse a CompanyProgram for the engagement using external_key/source based on engagement id + template_id.
   - create/reuse seven ProgramStageState rows.
   - ensure state_json includes department_slug, required, dependencies, inputs, outputs, blockers, skipped_reason, completed_by/started_by where relevant.
   - validate that required DepartmentRegistry rows exist for the engagement organization. If missing, raise a clear service error.
   - idempotently return the existing pipeline if already created.

D. Stage transitions:
   - start_stage: not_started/blocked/rerun_required -> in_progress if dependencies are completed or skipped with waiver only where allowed.
   - complete_stage: in_progress/awaiting_validation -> completed, record outputs and completed_at.
   - block_stage: any unfinished stage -> blocked with blocker reason.
   - skip_stage: only crm_lifecycle may be skipped for MVP, and reason is required. Other required stages cannot be skipped unless explicit waiver flag is added in payload/service call. Keep this simple.
   - client_approval_ops cannot complete unless qa_compliance is completed or has an explicit qa waiver in state_json.
