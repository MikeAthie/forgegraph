Goal:
When any ForgeGraph company run / department pipeline starts from a single prompt, the backend should automatically create visible task cards/routing records for the planned work, independent of business type. Today we are dogfooding a marketing agency for Legacy; tomorrow the same mechanism should work for a consulting firm, accounting firm, support operation, etc.

Critical correction:
- Do NOT hard-code "Legacy", "marketing agency", or the 7 Atlas department slugs inside the routing layer.
- The routing layer must derive tasks from the active `CompanyProgram` / `ProgramStageState` pipeline stage definitions and stage metadata.
- Legacy/Codex scripts may pass a run context, but the generic service should be reusable for any ordered stage plan.
- Card/task creation should be automatic at pipeline creation/bootstrap time, not manually authored per vertical.

Use existing primitives only:
- TaskRoutingRecord for visible durable task cards/routing trail.
- ProgramStageState.state_json for task/card cross-links and per-stage run state.
- ServiceDeliverable.metadata_json and AssetVersion.provenance_json for produced output provenance.
- WorkWhiteboard metadata/state as a denormalized backend-owned read snapshot, not source of truth.
- No new DB models/migrations unless absolutely unavoidable.

6. Assigned department should use existing department_slug/department_id metadata when available; fallback to stage_id.

8. Hook this generic bootstrap into department pipeline creation so cards exist automatically when a pipeline/program is created.
9. Hook the Legacy/Codex company run into the generic helpers, but keep Legacy-specific prompt/deliverable logic outside the generic routing service.
